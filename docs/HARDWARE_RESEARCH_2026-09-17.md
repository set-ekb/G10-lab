# G10: применение исследования Egret GT, 17.09.2026

## Вывод для проекта

Статья полезна как методика разделения блоков и пассивного исследования обмена.
Готовая прошивка Egret не является прошивкой YADEA G10. Проверенного нового кадра
управления G10, дампа его штатной прошивки или совместимого OTA в этом пакете нет.
Android APK v0.7 остаётся прежним: добавлены инструменты исследования в репозитории.

## Сопоставление

| Узел/уровень | Egret GT по авторской документации | Наш G10 по данным проекта |
|---|---|---|
| Основной MCU панели | AT32F415 | Не установлен |
| BLE | CH573, отдельный узел | Строки BEKEN SAS / BK-BLE-1.0; точный чип и топология платы не установлены |
| BLE-модуль ↔ MCU | UART; 55/AA, длина, индекс обработчика, CRC-16/XMODEM | Внутренний транспорт и формат не установлены |
| Панель ↔ контроллер ↔ батарея | CAN | UART/TTL — рабочая гипотеза; CAN не исключён |
| Получаемый приложением поток | Протокол из проекта Egret | FFF2, наблюдаемые 20 байт с заголовком 24 22 |
| Команды/обновление | Собственные обработчики и загрузчик | Достоверной совместимости с Egret нет |

UART-кадр между BLE-чипом и MCU не равен значению GATT-характеристики телефона.
По заголовкам разных уровней нельзя заключить, что на проводе G10 идёт FFF2 без
изменений. CRC Egret не назначаем пакетам G10. AT32F415 не объявляем MCU G10.

## Что осталось гипотезой из предыдущего обсуждения

- **Shenzhen RND Electronics:** направление поиска OEM, не установленный
  производитель конкретной платы пользователя. Нужен первичный документ с моделью
  и ревизией или читаемая маркировка самой платы.
- **KuKirin G4/G2:** кандидаты для сравнения фотографий, не совместимые доноры
  по умолчанию. Даже одинаковые разъём и корпус не доказывают распиновку.
- **E6 / serial communication:** прежняя ссылка на
  [страницу инструкции](https://www.manualslib.de/manual/1447751/Yadea-G10.html?page=42)
  в этом проходе недоступна. Формулировка о последовательной связи сама по себе
  не определяет электрический интерфейс: UART и уровни TTL требуют измерения.
- **BEKEN как мост:** правдоподобная схема, но строки Device Information не
  устанавливают физическое число MCU, модель чипа и связь с контроллером.

В [каталоге MotoTec есть контроллер G10 YD-0131](https://mototecusa.com/Yadea-G10-Controller-YD-0131).
Это артикул продавца, не номер PCB и не доказательство совпадения аппаратной
ревизии с нашим экземпляром. Читаемую распиновку G10 по этому источнику не получили.

## Что внедрено сейчас

`scripts/analyze_lab.py` читает готовый CSV LAB локально. Он не открывает BLE/COM,
не отправляет пакеты и не меняет настройки самоката.

- Отдельно считает FFF2_NOTIFY и FFF1_TX. Старые PROTOCOL_DETECT с копией HEX
  и FFF2_READ не увеличивают частоту уведомлений.
- Сохраняет одинаковые последовательные уведомления: это реальные измерения.
- Проверяет HEX и заявленную длину, показывает отвергнутые строки.
- Разделяет потоки по UUID, длине и первым двум байтам. Это группировка,
  а не автоматическое определение совместимой модели.
- Показывает частоту, максимальный разрыв, меняющиеся байты/биты и распределение
  значений по меткам; поддерживает старое и новое имя столбца примечаний.
- Сбитое время не превращается в ложную частоту. Единственный пакет частоты не даёт.
- Метка TX не переносится на последующую телеметрию как подтверждённое состояние.
- JSON содержит SHA-256 входного файла. Метки — наблюдения пользователя, не ACK;
  различия распределений могут быть вызваны дрейфом напряжения или порядком опыта.

Запуск из корня репозитория (Python 3, без сторонних библиотек):

```bash
python scripts/analyze_lab.py lab-samples/g10_ble_20260812_174109.csv
python scripts/analyze_lab.py /path/to/export.csv --json
python -B -m unittest discover -s scripts -p 'test_analyze_lab.py' -v
```

На имеющемся образце: 49 FFF2, один TX `F0 4D 13`, ошибок строк нет;
интервал FFF2 13.973 с, частота 3.435 Гц, максимальный разрыв 0.357 с.
Меняется только байт 4. Это не доказывает ответ на запрос круиза и не является
новым полевым испытанием. Уже установленный `check_lab_sample.sh` проверяет
32 уведомления после исторического запроса; этот запрос повторять не нужно.

## Следующий захват без разборки

В LAB v0.7 уже есть метки. Для каждого штатного действия выполнить отдельную
запись на стоящем самокате: 10–15 с исходного состояния, действие штатной кнопкой,
10–15 с нового состояния, возврат в исходное, повтор 2–3 раза. Метки, например:
`BRAKE_OFF`, `BRAKE_ON`, `LIGHT_OFF`, `LIGHT_ON`.

Свет проверять штатной кнопкой только при наличии такой функции. Режимы менять
на остановке; отмечать реально показанный режим панели, а не нажатие в приложении.
Один опыт — одна переменная. Отсутствие изменения FFF2 не означает отсутствие
команды: информация может идти по другому каналу. LAB видит обмен нашего
приложения; он не перехватывает команды другого приложения.

## Аппаратное исследование на отдельных сервисных узлах

Для согласованного стенда нужны дисплей и контроллер **с совпадающими артикулами
и ревизиями G10**. Пока этого не проверили, детали KuKirin не подбирать как замену.

1. Снять крупные фото обеих сторон PCB, надписей всех MCU/радиомодуля, наклеек,
   разъёмов с ключами и количества контактов. Отметить ориентацию нумерации.
2. Заполнить паспорт ниже. Не назначать RX/TX/GND по цветам проводов или внешнему
   сходству. Сначала установить землю, питание и уровни сигналов измерениями;
   питание самоката не подключать ко входам логического анализатора.
3. После определения уровней и интерфейса снять только пассивную запись запуска,
   простоя, тормоза и света. Для UART сохранить обе линии раздельно; для CAN
   использовать соответствующий трансивер и режим прослушивания. Сохранить сырые
   сигналы: скорость, полярность и границы кадров пока могут оказаться неверными.
4. Сопоставить изменения со штатным действием и повторить опыт. Только после
   этого присваивать полю смысл. Новый анализатор принимает BLE LAB, не сырые UART/CAN.
5. Для OTA сначала получить модель/код платы, версию, исходный URL и SHA-256
   родного файла обновления. План резервирования и восстановления зависит от
   установленного MCU/загрузчика. Чужой flasher Egret на G10 не запускать.

| Поле паспорта | Панель | Контроллер |
|---|---|---|
| Фото наклейки, номер детали | требуется | требуется |
| PCB и ревизия | неизвестны | неизвестны |
| Полная маркировка MCU | неизвестна | неизвестна |
| Радиомодуль/трансивер | неизвестен | неизвестен |
| Разъём, ключ, нумерация | требуется | требуется |
| Проверенные питание/земля | не измерены | не измерены |
| Тип связи, уровни, скорость | не измерены | не измерены |
| Файл штатной прошивки, SHA-256 | не получен | не получен |

Паспорт и новые логи позволят выбрать следующий кодовый пакет без подстановки
неподтверждённых параметров в приложение.

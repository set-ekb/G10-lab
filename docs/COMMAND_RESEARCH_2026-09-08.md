# G10: команды и источники, проверка 08.09.2026

Исследование относится к YADEA G10 пользователя (FFF0/FFF1/FFF2, BEKEN BK-BLE-1.0,
FW 6.1.2 / SW 6.3.0). Новых публично подтверждённых управляющих кадров именно
для этого G10 в проверенных источниках не найдено. Совпадение названия чипа или
UUID не устанавливает совместимость контроллеров.

## Рабочий справочник

Индексы байтов ниже **с нуля**. «Подтверждено в проекте» означает локальные
исследования/PROJECT_STATE, а не спецификацию, опубликованную Yadea.

| Функция | Кадр / поле | Основание | Поведение v0.7 |
|---|---|---|---|
| ECO | `F0 4C 03 01` → FFF1 | Подтверждено в PROJECT_STATE | Только на остановке, свежий FFF2 ≤2 с, пауза между командами ≥750 мс |
| SPORT | `F0 4C 03 02` → FFF1 | То же | То же |
| RACE | `F0 4C 03 03` → FFF1 | То же | То же |
| Подтверждение режима | Не установлено | FFF2 не даёт проверенного ACK режима | «Запрошен …, проверьте дисплей». В поездку не записывается выдуманный режим |
| Напряжение | `(p[4] + 256*p[5])/100`, В | Локальные наблюдения потока `24 22`, 20 байт | Показывается только по свежему распознанному потоку |
| Скорость | `p[12]`, км/ч | Локальные наблюдения | То же |
| Тормоз | `p[18] & 0x08` | Локальные логи: `40↔48` | Индикатор тормоза |
| Движение | `p[18] & 0x02` | Рабочая гипотеза прежнего декодера | Дополнительный запрет смены режима, не отдельное доказательство остановки |
| Круиз | `p[18] & 0x04` | Гипотеза, не подтверждённое управление | На главном экране не выдаётся за установленный статус |
| Запрос `F0 4D 13` | Назначение не установлено | Образец 12.08: отдельного ответа после запроса не обнаружено | Не отправляется |
| Свет / LOCK / Zero Start / рекуперация / TCS / круиз ON/OFF | Кадры не установлены | Описание функций приложений не раскрывает протокол G10 | Не отправляются |
| OTA / OAD | Совместимость не установлена | Нужен аппаратный код платы, не только версия общего BLE-модуля | Запись прошивки не реализована |
| Ток, мощность, температура BMS, BMS SOC | Поля не установлены | Нет проверенной расшифровки | Значения не подставляются; заряд и км явно оценочные |

При неизвестном заголовке/длине пакет сохраняется в LAB без декодирования. Поток
`55 AA`, `5A A5` или `F1` не принимается за наш `24 22`. Названия семейств в
LAB — диагностические метки, не определение совместимой прошивки.

## Проверка кода, связанная с этими данными

- Режим не подменяется локально созданной «телеметрией» после успешной очереди GATT.
- CCCD считается включённым после успешного `onDescriptorWrite`, не сразу после вызова write.
- Устаревшие callbacks прежнего соединения игнорируются. Потеря свежести убирает скорость,
  напряжение и прогноз с приборов; GPS-точки не продолжают получать старое напряжение.
- В CSV одна строка на уведомление; PROTOCOL_DETECT пишет только смену семейства без HEX-дубля.

Справка Android: [GATT callbacks](https://developer.android.com/reference/android/bluetooth/BluetoothGattCallback).

## Что требуется для расширения

Для каждой новой функции нужен парный пассивный лог «до / штатная команда / после»
именно на этом G10, с соответствующей версией приложения и аппарата. Для OTA —
метаданные совместимости платы и хеш оригинального файла. Найденные на форумах
коды не добавляются в отправитель автоматически.

# G10 BLE Lab v0.2

Безопасный диагностический клиент для YADEA G10 с BLE-модулем BEKEN `BK-BLE-1.0`.

## Что делает v0.2

- находит BLE-устройство с именем `G10`;
- подключается к GATT;
- проверяет `FFF0 / FFF1 / FFF2`;
- читает Manufacturer / Model / Firmware / Software;
- читает Battery Service, если контроллер его отдаёт;
- подписывается на `FFF2 Notify`;
- показывает все входящие пакеты в HEX;
- считает длины пакетов;
- сравнивает соседние FFF2-пакеты и показывает номера изменившихся байтов;
- считает, какие позиции байтов меняются чаще всего;
- позволяет вручную ставить безопасные метки теста: `СТОИТ`, `КОЛЕСО`, `ТОРМОЗ`, `ECO`, `DRIVE`, `SPORT`;
- экспортирует CSV с длиной пакета, изменившимися позициями и текущей меткой.

## Безопасность

Версия 0.2 остаётся **READ ONLY** по отношению к прикладному протоколу самоката.

В коде нет отправки команд в `FFF1` и нет обращения к OTA/OAD-сервису. Единственная GATT-запись — стандартный CCCD `0x2902`, необходимый для включения уведомлений `FFF2`.

## Известный BLE-профиль G10

- BLE name: `G10`
- Manufacturer: `BEKEN SAS`
- Model: `BK-BLE-1.0`
- Firmware: `6.1.2`
- Software: `6.3.0`
- Service: `0000FFF0-0000-1000-8000-00805F9B34FB`
- `FFF1`: Write Without Response — **v0.2 не использует**
- `FFF2`: Read / Notify — основной канал наблюдения

## Сборка через GitHub Actions

В проект уже добавлен файл:

`.github/workflows/android-debug-apk.yml`

После загрузки проекта в GitHub:

1. Открой вкладку **Actions**.
2. Выбери **Build Android APK**.
3. Нажми **Run workflow**.
4. После успешной сборки открой завершённый запуск.
5. Внизу страницы в **Artifacts** скачай `G10BleLab-v0.2-debug-apk`.
6. В архиве будет `app-debug.apk`.

Workflow использует JDK 17 и Gradle 8.13.

## Первый диагностический тест

1. Закрой LightBlue, YADEA и другие программы, которые могут удерживать BLE-соединение.
2. Включи самокат.
3. Запусти G10 BLE Lab.
4. Нажми **Сканировать G10**.
5. После подключения подожди 20–30 секунд.

Если `Пакетов FFF2` остаётся `0`, ничего страшного: возможно, телеметрия начинается только после handshake. В v0.2 handshake намеренно не отправляется.

Если пакеты идут, сделай короткую серию тестов:

- нажми `СТОИТ`, не трогай самокат 10 секунд;
- нажми `КОЛЕСО`, приподними ведущее колесо и плавно прокрути/запусти его штатным способом;
- нажми `ТОРМОЗ`, несколько раз нажми тормоз;
- по очереди включи штатными органами управления режимы и нажимай в приложении соответствующие `ECO`, `DRIVE`, `SPORT`;
- экспортируй CSV.

Важно: кнопки в приложении **ничем не управляют**. Они только записывают метку в журнал, чтобы потом сопоставить изменение байтов с действием на самокате.

## Что будет в v0.3

После получения первого реального CSV можно построить корреляцию по байтам и начать выделять кандидатов на:

- скорость;
- заряд / напряжение;
- режим;
- тормоз;
- свет;
- пробег;
- ошибки.

Команды записи в FFF1 будем добавлять только после того, как формат пакетов и контрольные суммы будут подтверждены.

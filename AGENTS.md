# G10 Companion — agent instructions

Цель: минимизировать расход контекста и Work/Codex при разработке, не ухудшая качество и безопасность изменений.

## Обязательный порядок чтения

1. `AGENTS.md` — правила работы.
2. `docs/PROJECT_STATE.md` — короткое стабильное состояние проекта.
3. `docs/NEXT_BUILD.md` — только утверждённые задачи следующего пакета.
4. Затем открывать только файлы, непосредственно относящиеся к задаче.

Не перечитывать весь `README.md`, историю чата, все логи/CSV и весь репозиторий без необходимости.

## Экономия контекста

- Сначала определить минимальный набор файлов для изменения.
- Для локального изменения читать нужные методы/соседние участки, а не полный крупный файл.
- `app/src/main/java/com/g10blelab/app/MainActivity.java` большой (~68 КБ): читать только при изменениях экранов, навигации между вкладками или связывании UI с логикой.
- `G10BleManager.java` (~24 КБ): читать только для BLE-подключения, GATT, телеметрии и подтверждённых команд.
- `TripAnalysisEngine.java` (~20 КБ) и `TripTracker.java` (~18 КБ): читать только для записи/анализа поездки, GPS и обучения.
- `RouteEnergyEstimator.java` (~14 КБ): читать только для прогноза дальности/остатка и параметров маршрута.
- `BatteryCoach.java` (~11 КБ): читать только для батарейной модели, SOC/SOH и обучения.
- `route_map.html` (~10 КБ): читать только для карты, поиска адреса и построения маршрута.
- CSV/логи: сначала извлекать короткую диагностическую выжимку; полный лог читать только если это нужно для протокола или статистики.
- Не делать попутный рефакторинг вне утверждённого пакета.

## Карта проекта

- `app/src/main/java/com/g10blelab/app/MainActivity.java` — основной Android UI.
- `G10BleManager.java` — BLE/GATT и телеметрия.
- `TripTracker.java` — запись поездки.
- `TripAnalysisEngine.java` — анализ поездки и качества данных.
- `BatteryCoach.java` — батарейная модель и обучение.
- `RouteEnergyEstimator.java` — прогноз поездки/остатка.
- `AppDataBackup.java` — резервная копия данных.
- `TrackView.java` — визуализация GPS-трека.
- `app/src/main/assets/route_map.html` — OSM/маршрутный UI.
- `core-tests/` — тесты расчётного ядра.
- `lab-samples/` — только диагностические образцы, не общий контекст.
- `scripts/` — локальные проверки ядра и лабораторных образцов.

## Неподвижные ограничения

- Сохранять тот же Android `applicationId` и постоянную тестовую подпись, чтобы обновления APK не теряли профиль, обучение и историю.
- Не отправлять неизвестные BLE-команды ради эксперимента.
- Подтверждённые команды режима ECO/SPORT/RACE разрешать только при соблюдении существующих проверок безопасности.
- Не выдавать оценочный SOC за точный BMS SOC, пока протокол этого не подтверждает.
- Не придумывать Wh/км, ток, SOH или другие значения, которых нет в подтверждённой телеметрии.
- Карта/поиск/маршрут могут использовать внешние открытые сервисы только в рамках существующей модели приватности.

## Правило агентной итерации

Одна агентная итерация = один связанный пакет изменений. Перед кодом перечислить файлы, которые реально нужны. После реализации запускать только релевантные проверки; полный Android build — для готового пакета или риска интеграции, а не для каждой текстовой/косметической правки.
